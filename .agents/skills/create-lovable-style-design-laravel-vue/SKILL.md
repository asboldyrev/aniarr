# Когда использовать
- При необходимости создать новый дизайн или страницу, вдохновленную эстетикой Lovable.dev.
- Когда нужно перенести визуальную концепцию из React-проектов Lovable в среду Laravel + Vue 3.
- Для быстрой прототипизации интерфейсов с использованием `shadcn-vue` и Tailwind CSS v4.

# Когда НЕ использовать
- Для реализации сложной бизнес-логики или реальных API-запросов (скилл ориентирован только на дизайн и моки).
- Если проект не использует Vue 3 или Tailwind CSS.

# Требования к вводу
1. **Описание задачи**: Что именно нужно создать (страницу, компонент, дашборд).
2. **Настройки темы**: Пользователь должен подтвердить, что в `resources/css/app.css` (или аналогичный файл) добавлены базовые стили темы (переменные oklch/hsl).
3. **Разрешение на кастомизацию**: Скилл ОБЯЗАН спросить: "Могу ли я самостоятельно настраивать стили компонентов (отступы, размеры, радиусы) для лучшего соответствия тематике проекта?".
    - Если **НЕТ**: использовать стандартные значения из текущего проекта.
    - Если **ДА**: адаптировать стили под тематику, соблюдая правила хорошего дизайна.

# Концепция дизайна Lovable (UI/UX)
При создании дизайна придерживайтесь следующих принципов:
1. **Сетка и Пространство**: Использование `max-w-5xl` или `max-w-7xl` для контента, щедрые отступы (`p-6`, `gap-6`), `sticky` хедеры с эффектом `backdrop-blur`.
2. **Визуальный стиль**:
    - Мягкие скругления (`rounded-xl`, `rounded-2xl`).
    - Тонкие границы (`border-border/50`).
    - Использование `oklch` для цветов (если поддерживает тема).
    - Карточная структура для группировки контента (`bg-card`).
3. **Компоненты**:
    - **Sidebar**: Адаптивная боковая панель с использованием `shadcn-vue` Sidebar.
    - **Empty States**: Обязательное наличие иллюстрации (placeholder) и четкого CTA для пустых состояний.
    - **Stats**: Карточки с иконками в цветных подложках (`bg-primary/10`).
4. **Интерактивность**: Добавление `transition-all`, `hover:shadow-lg`, моковые состояния загрузки или переключения вкладок.

# Рабочий процесс

1. **Анализ и запрос**:
    - Изучить запрос пользователя.
    - Спросить про разрешение на кастомизацию стилей.
    - Уточнить наличие базовых стилей темы в CSS.

2. **Структура файлов (Laravel/Vue)**:
    - Страницы: `resources/js/pages/*.vue`
    - Компоненты: `resources/js/components/*.vue`
    - UI-компоненты: `resources/js/components/ui/**/*.vue` (использовать существующие или создавать новые через shadcn-vue).

3. **Реализация дизайна**:
    - Создать Vue-компонент с использованием Composition API (`<script setup>`).
    - Использовать Tailwind CSS v4 для стилизации.
    - Добавить моковые данные (например, константы внутри компонента) для отображения списков, таблиц или графиков.
    - Реализовать базовую реактивность (открытие диалогов, переключение табов) без обращения к бэкенду.

4. **Проверка**:
    - Убедиться, что дизайн выглядит целостно и современно.
    - Проверить адаптивность (мобильная версия).
    - Проверить соответствие выбранному режиму кастомизации.

# Примеры

### Запрос на кастомизацию
> "Я создам дизайн дашборда. Могу ли я самостоятельно настроить размеры инпутов и отступы для этого проекта, или мне строго следовать текущим настройкам?"

### Моковая логика
```vue
<script setup>
import { ref } from 'vue'
const items = ref([
  { id: 1, name: 'Mock Item 1', status: 'active' },
  { id: 2, name: 'Mock Item 2', status: 'pending' },
])
const deleteItem = (id) => {
  // Только визуальная реакция
  items.value = items.value.filter(i => i.id !== id)
}
</script>
```
